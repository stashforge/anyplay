# Task Tracking

Before continuing work, read docs/TASKS.md. It is the source of truth for current
status and ordering. Use docs/README.md to find the relevant design/detail note;
do not rescan all documentation or treat archived next-step statements as current.

Announce the task ID and a small deliverable before implementation. Update the
board in place after each slice with actual scope, verification and remaining
work. Distinguish foundation, live wiring and user acceptance. Do not append
routine checkpoints to archived logs or silently drop unresolved tasks.

Keep checkpoints short for user review. Manual testing instructions must state
where to test and the expected behavior; say when no visible change exists.
For bug reports, inspect logs and owning code before proposing a fix. Routine
verification uses Python 3.10 only. Do not commit or push without authorization.
